## 0. 스터디 규칙 → 내 작업에 미치는 영향

스터디 원칙이 "**설명할 수 없는 코드는 내 코드가 아니다**"이고, 이슈 3항목이
`작업 내용` / `Deep Dive 해본 것` / `알게된 것` 입니다. 여기서 나오는 실질적 제약:

- **Deep Dive가 이슈의 중심.** "이번 주 뭘 만들었다"는 1/3이고, 나머지 2/3는 **하나를 깊게 판 기록**.
  → 매주 **"깊게 팔 주제 1개"를 미리 정해놓고** 작업하는 게 유리. 만들다 보면 자동으로 생기지 않음.
- **토론은 설계의 전제·근거·트레이드오프를 겨냥.** 다른 참가자가 물을 질문을 미리 상정하고 작업.
- **실패 사례일수록 큰 학습.** naive 구현 → 측정 → 개선 흐름이 이 스터디 포맷과 정확히 맞음.
  → 각 주차마다 **"순진한 버전을 일부러 먼저 만들고 측정한다"**를 기본 루틴으로.

### 문서 두 벌 쓰기 (중복 아님)

|---|---|---|
| 스터디 레포 **Issue** | 3항목 (작업/DeepDive/알게된것) | 공개·토론용. **간결**하게 |

### Week 02 — 백엔드 골격 (진행 중)

**① 만들 것**: `/health`, SQLModel 3테이블, 시뮬레이터 루프, `WS /ws/telemetry`, REST 2개, 배치 저장, compose

**② 깊게 팔 후보** (하나만 고르세요 — 1순위 추천)

1. **⭐ 쓰기 부하: 매 tick INSERT vs 메모리+배치**
   - 로봇 5,000대 × 100ms tick = **초당 5만 INSERT**. SQLite는 물론 Postgres도 부담.
   - 파볼 것: 트랜잭션으로 묶기(개별 commit이 왜 느린가 = fsync), `executemany`,
     SQLite **WAL 모드**, 배치 주기(5초)와 **데이터 해상도의 트레이드오프**
     ("과거 조회를 5초 간격으로만 볼 수 있게 된다 — 그래도 괜찮은가?"),
     **다운샘플링 vs 전량 저장** 중 무엇을 택했나.
   - 측정 그림: naive(매 tick commit) 1분 실행 → 배치 버전 1분 실행 → **INSERT/s, 소요시간, DB 파일 크기** 비교표.
2. **WebSocket 브로드캐스트 팬아웃**
   - 클라 C개 × 로봇 N개 = 매 tick C×N 데이터. 파볼 것: 끊긴 소켓 정리(안 하면 리스트가 샘),
     **backpressure**(느린 클라이언트 하나가 전체 루프를 막는 문제), 순차 `await send` vs `asyncio.gather`,
     JSON 직렬화 비용(매 클라마다 다시 직렬화 vs 한 번 만들어 재사용).
3. **FastAPI에서 백그라운드 루프를 어디에 다나**
   - `lifespan` vs `BackgroundTasks` vs `asyncio.create_task`. 이벤트 루프를 블로킹하면
     API 응답까지 멈추는 이유(단일 스레드 asyncio), `time.sleep` vs `await asyncio.sleep`.
4. **스키마: 왜 3테이블로 쪼개나**
   - `robots`(현재상태, 행 N개 고정) / `telemetry`(시계열, 무한 증가) / `alerts`(이벤트).
   - 파볼 것: 복합 인덱스 `(robot_id, recorded_at)`가 왜 그 순서인가, FK 걸었을 때 대량 INSERT 비용.

**③ 예상 질문**
- "배치 주기 5초는 어떻게 정했나? 서버가 죽으면 그 5초는 날아가는데 괜찮은가?"
- "메모리에 5,000대 상태를 들고 있으면 서버 인스턴스를 2개로 못 늘리는데, 그건 인정하고 가는 건가?"
- "SQLite로 시작한 게 5주차 이전 비용을 키우는 것 아닌가?"

### Week 03 — 프론트 실시간 파이프라인

**① 만들 것**: WS 수신 → Jotai → 렌더, 가상화 데이터그리드(50,000행), **baseline 측정**

**② 깊게 팔 후보**

1. **⭐ 초당 수천 업데이트 → React 리렌더 폭발**
   - 순진한 버전: `useState`에 로봇 배열 통째로 → 로봇 1대 움직여도 **전체 리스트 리렌더**.
   - 파볼 것: Jotai `atomFamily`로 로봇당 원자 분리 → 구독한 컴포넌트만 리렌더.
     "왜 Context는 이 문제를 못 푸나"(Context는 값이 바뀌면 구독자 전원 리렌더).
   - 측정: React DevTools Profiler로 **커밋 횟수 / 커밋당 시간** before-after.
2. **WS 메시지 배칭 — 네트워크 tick과 렌더 tick 분리**
   - 서버가 100ms마다 보내도 브라우저는 16.6ms마다 그림. 반대로 서버가 10ms마다 보내면?
   - 파볼 것: `requestAnimationFrame` 기준으로 메시지 병합, throttle vs debounce vs 프레임 병합의 차이.
3. **가상화가 실제로 무엇을 아끼나**
   - 50,000행 DOM = 리플로우 지옥. 파볼 것: 화면 밖 행을 안 만드는 것 vs 만들고 숨기는 것,
     가변 높이일 때의 스크롤 점프 문제.

**③ 예상 질문**
- "atom을 로봇 수만큼 만들면 atom 자체의 오버헤드는? 5,000개 atom은 괜찮나?"
- "60fps로 못 그릴 바엔 서버 tick을 늦추는 게 낫지 않나 — 어디서 버려야 하나?"

### Week 04 — 3D 대용량 렌더 ★ 포트폴리오 핵심

**① 만들 것**: R3F 3D 뷰, 인스턴싱·LOD·프러스텀 컬링, 1,000대 60fps / 5,000대 30fps

**② 깊게 팔 후보**

1. **⭐ draw call 1000 → 1 (InstancedMesh)**
   - `<mesh>` 1,000개 = **draw call 1,000회** = CPU가 GPU에 1,000번 명령. 이게 병목.
   - 파볼 것: `InstancedMesh`로 1회 호출에 1,000개 그리기, `instanceMatrix` 직접 갱신,
     "왜 색까지 다르게 하려면 `instanceColor`가 따로 필요한가".
   - 측정: r3f-perf로 **draw calls / fps** before-after — 이 표 하나가 포트폴리오 대표 이미지.
2. **R3F에서 React state를 쓰면 안 되는 지점**
   - 위치를 `useState`에 넣고 매 프레임 `setState` = 초당 60번 React 렌더 트리 순회.
   - 파볼 것: `useFrame` 안에서 `ref.current.position` **직접 mutate**(React 렌더 사이클 우회),
     "선언형 React와 명령형 애니메이션의 경계를 어디에 긋나" ← 토론감으로 아주 좋음.
3. **100ms tick을 60fps로 부드럽게 (보간)**
   - 데이터는 100ms마다 오는데 화면은 16.6ms마다 그림 → 그대로 쓰면 뚝뚝 끊김.
   - 파볼 것: lerp 보간, **보간은 "없는 데이터를 지어내는 것"인데 관제 대시보드에서 허용되나**
     (시각적 부드러움 vs 데이터 정확성 — 좋은 윤리/설계 논점).
4. **LOD·프러스텀 컬링**: 멀리 있는 건 단순 도형으로, 화면 밖은 아예 안 그림. 언제 이득이고 언제 오히려 손해인가.

**③ 예상 질문**
- "인스턴싱하면 개별 로봇 클릭 판정은 어떻게 하나?" (raycasting + instanceId)
- "5,000대에서 30fps면 성공인가 실패인가 — 기준은 누가 정했나?"

### Week 05 — Postgres 이전

**① 만들 것**: docker `db` 서비스, SQLite→Postgres 마이그레이션, 시계열 집계, (stretch) GraphQL

**② 깊게 팔 후보**

1. **⭐ SQLite vs Postgres — 동시성 모델의 차이**
   - SQLite: **파일 락**(쓰기 1개만). Postgres: **MVCC**(읽는 사람이 쓰는 사람을 안 막음).
   - 파볼 것: 왜 2주차엔 SQLite로 버텼나(=쓰기가 배치 하나뿐이라 경합이 없었음),
     동시 쓰기가 생기는 순간 무엇이 깨지는가, 타입 시스템 차이(SQLite 동적 타입의 함정).
2. **마이그레이션 자체를 사례로**
   - Alembic 도입, 스키마 변경을 코드로 관리, "기존 데이터는 어떻게 옮기나 / 다운타임은".
3. **시계열 집계 & 쿼리 튜닝**
   - "지난 1시간 배터리 추이"를 5,000대 × 1시간치에서 뽑기. `EXPLAIN ANALYZE` 읽는 법,
     인덱스 유무 차이, 다운샘플링(1분 평균) 사전 계산 vs 조회 시 계산.
4. **(stretch) REST vs GraphQL 과다수신**: 오버페칭 실측. 시간 없으면 **버려도 되는 항목**.

**③ 예상 질문**
- "처음부터 Postgres로 갔으면 이 주차가 통째로 필요 없었는데, 그건 낭비 아닌가?"
  → 답할 준비: 학습 목적 vs 실무 판단을 분리해서 설명.

**② 깊게 팔 후보**

1. **⭐ Vercel이 숨겨주던 것**
   - `git push` 한 번에 되던 게 실제로는 빌드→아티팩트→서빙→캐시 헤더→롤백.

3. **실시간을 어떻게 테스트하나**: WS·타이머·랜덤이 들어간 코드의 테스트 전략(가짜 타이머, 시뮬레이터 시드 고정).
